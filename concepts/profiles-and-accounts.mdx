Everything in PlugKit hangs off three objects. Understanding them makes the rest
of the API obvious.

<Steps>
  <Step title="Your account" icon="user">
    Created when you sign in to the [dashboard](https://plugkit.co/dashboard).
    Every profile, account, post and conversation is **scoped to you** — an API
    key only ever sees your own data.
  </Step>
  <Step title="Profiles" icon="folder">
    A **profile** is a workspace / brand that groups connected accounts. You can
    have several (e.g. one per client). Create one before connecting anything.
  </Step>
  <Step title="Accounts" icon="link">
    An **account** is a connected social/messaging identity (an Instagram
    business account, a Telegram bot, …) living inside a profile. You act on the
    world through accounts.
  </Step>
</Steps>

```bash Create a profile
curl -X POST https://api.plugkit.co/v1/profiles \
  -H "Authorization: Bearer sk_your_key" \
  -H "Content-Type: application/json" \
  -d '{ "name": "My brand" }'
```

## How you connect accounts

Each platform uses one of three patterns. The [platform pages](/platforms/instagram)
document the exact flow and specifics for each.

| Pattern | Platforms | How |
| --- | --- | --- |
| **OAuth redirect** | Instagram, Facebook, Threads, TikTok, YouTube, X, LinkedIn, Bluesky, Meta Ads, Google Ads | `GET /connect/{platform}?profileId=…` → open the returned `authUrl` → the platform redirects back and PlugKit stores the token |
| **Embedded Signup** | WhatsApp | `GET /connect/whatsapp?profileId=…` — same shape, but the user brings their own number and WhatsApp Business Account |
| **Bot token** | Telegram | `POST /connect/telegram` with a token from @BotFather |

One authorization can create **several accounts**: a Facebook login granting
three Pages produces three accounts, and the same screen can grant ad accounts
too.

Useful query parameters on `GET /connect/{platform}`:

| Parameter | Effect |
| --- | --- |
| `accountId` | Reconnect that account (its token is replaced) instead of creating a new one. |
| `switchAccount=true` | Instagram: ask for credentials again, to connect a different account than the one open in the browser. |
| `handle` | Bluesky: the handle of an account hosted outside bsky.social. |
| `coexistence=true` | WhatsApp: keep the number in the WhatsApp Business app. |

### Connect links for your clients

When the person who owns the social accounts isn't you, create a **connect
link** for a profile and send it to them. They open it, pick the platforms, and
the accounts land in that profile — no PlugKit login on their side:

```bash
curl -X POST https://api.plugkit.co/v1/connect-invites \
  -H "Authorization: Bearer sk_your_key" -H "Content-Type: application/json" \
  -d '{ "profileId": "PROFILE_ID" }'
# → { "url": "https://…", "expiresAt": "…" }
```

The link is valid 30 days. Creating a new one revokes the previous link of that
profile; `GET /connect-invites?profileId=…` tells you whether one is active and
`DELETE /connect-invites?profileId=…` revokes it.

## Managing accounts

```bash List accounts
curl "https://api.plugkit.co/v1/accounts?profileId=PROFILE_ID&status=active" \
  -H "Authorization: Bearer sk_your_key"
```

Filters: `profileId`, `platform`, `status` (`active` or `disconnected`), plus
`page`/`limit`. Each account exposes its `_id`, `platform`, `username`,
`displayName`, the `profileId` it belongs to, and its health — never its access
token:

| Field | Meaning |
| --- | --- |
| `isActive` | The account can publish and message. |
| `needsReconnection` | The opposite of `isActive`: disconnected on purpose, or its token died (password change, expired session…). |
| `disconnectedReason` | Present when PlugKit knows why. |

```bash Disconnect
curl -X DELETE https://api.plugkit.co/v1/accounts/ACCOUNT_ID \
  -H "Authorization: Bearer sk_your_key"
```

Disconnecting drops the token but keeps the account (and its history) in the
list, so it can be reconnected with `GET /connect/{platform}?accountId=…`. To
remove a disconnected account for good — along with its publication history and
conversations — call `DELETE /accounts/{id}/permanent`.

<Note>
  Requesting a resource that belongs to another account returns `404`, not
  `403`, so keys can't probe for existence.
</Note>
